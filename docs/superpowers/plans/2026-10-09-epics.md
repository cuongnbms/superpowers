# Epics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Brainstorming writes a request's split into features as an epic file, continues an epic from its path, and finishing-a-development-branch names the next feature with a paste-ready prompt.

**Architecture:** Skill prose changes in brainstorming (new `epic-format.md` plus edits to `SKILL.md`), finishing-a-development-branch (Step 3 capture, new Step 7), and one-line touches in writing-plans and using-git-worktrees. Each behavior is pinned by an eval case. All eval runs happen together in Task 6, after the edits, as your human partner asked: the old skill is a snapshot from `dev`, so its baseline is the same whenever it runs.

**Tech Stack:** Markdown skills; bash setup scripts; git; Opus subagents for eval runs.

**Spec:** `docs/superpowers/specs/2026-10-09-epics-design.md`

## Global Constraints

- Terms: **Epic** and **Feature** only. New skill text never says "roadmap" or "sub-project" (RELEASE-NOTES may name upstream's "sub-project" when explaining the departure).
- Exact strings, used identically in every file that mentions them:
  - epic path pattern `docs/superpowers/epics/YYYY-MM-DD-<topic>.md`
  - spec header line `> **Epic:** <epic path> § <letter>`
  - epic headings `## Findings`, `## Shared decisions`, `## Features`, feature heading `### <letter>. <name>`
  - feature fields `Scope:`, `Depends on:`, `Decide when brainstormed:`
  - state labels `not started`, `on <branch>`, `on <base>`
  - paste-ready prompt `Brainstorm feature <letter> of <epic path>`
- State derivation command (in `epic-format.md` and repeated in finishing):
  `git grep -n "Epic:.*$(basename "$EPIC")" $(git for-each-ref --format='%(refname:short)' refs/heads refs/remotes) -- '*.md'`
  A spec on the base wins over the same letter on any other branch.
- Skill voice: match the surrounding file: "your human partner", plain declaratives with the reason attached, no MUST/NEVER capitals, no new emphasis. `brainstorming/SKILL.md` wraps at about 95 columns; `finishing-a-development-branch/SKILL.md` at about 72 inside prose sections.
- Eval runs: Agent tool, `model: opus`, one subagent per run, prompt shape from `skills/writing-skills/references/eval-workflow.md` Step 1. Old skill = snapshot from `dev` (`git show dev:<path>`) under `$SCRATCH/epics-evals/old/`. Workspaces under `$SCRATCH/epics-evals/iteration-N/eval-<id>-<name>/{old_skill,new_skill}/run-K/`, where `$SCRATCH` is this session's scratchpad. Grade inline into `grading.json` (`expectations[{text, passed, evidence}]` + `summary{total, passed, failed, pass_rate}`); read every mechanical hit before counting it.
- Setup scripts commit with `-c user.email=eval@example.com -c user.name=eval -c commit.gpgsign=false`, like `skills/subagent-driven-development/evals/setup-case.sh`, and use `set -euo pipefail`.
- Release version: `6.4.24`.

## Review Focus

1. A merged feature whose branch was never deleted (spec on `main` and on `feat/a`): it must read `on main`, not `on feat/a`. Pinned in Task 1's `continue` setup, which keeps `feat/a` after merging it, and in case 11's expectations.
2. Finishing reached with no remote: Option 1's `git pull` fails on a repo with no upstream and can derail the case. Task 2's setup gives the repo a bare `origin` so the merge path runs as written, which also puts `refs/remotes` in the derivation.

```python
import io
import json
import tempfile
import unittest
from contextlib import redirect_stdout
from pathlib import Path

import todo


class TodoTest(unittest.TestCase):
    def setUp(self):
        self.dir = tempfile.TemporaryDirectory()
        todo.STORE = Path(self.dir.name) / "todo.json"

    def tearDown(self):
        self.dir.cleanup()

    def run_cli(self, *argv):
        out = io.StringIO()
        with redirect_stdout(out):
            todo.main(list(argv))
        return out.getvalue()

    def test_add_and_list(self):
        self.run_cli("add", "milk")
        self.assertEqual(self.run_cli("list"), "[ ] #1 milk\n")

    def test_done(self):
        self.run_cli("add", "milk")
        self.run_cli("done", "1")
        self.assertEqual(self.run_cli("list"), "[x] #1 milk\n")


if __name__ == "__main__":
    unittest.main()
```
